# 23 — State Machines

Notation: state →(actor, condition)→ next. Invalid transitions → 422 + audit.

**Purchase Order:** draft →(creator)→ submitted →(approver≠creator)→ approved →(purchaser)→ ordered →(receipt)→ partially_received ↔(receipt)→ fully_received →(close)→ closed. submitted →(reject)→ draft (version++). draft|submitted|approved (received==0) →(cancel)→ cancelled. ordered|partially_received →(close with reason, remainder noted)→ closed. Cancel after ANY receipt posted is forbidden (close instead).
**Stock Count (new, normative):** open →(staff: first count entry)→ counting →(submit)→ variance_review →(approver≠creator and ≠ every counter)→ approved →(`count_apply`)→ applied (terminal = closed). counting allows concurrent postings (no freeze); variance recomputed at apply under lock per INV-023; large variance (configurable %) forces recount → back to counting; variance_review →(recount chosen lines)→ counting. Cancel allowed pre-apply only.
  *Build decisions (Part 8):* the snapshot (`snapshot_at`, `snapshot_qty` per bin/variant/batch with on_hand > 0, optionally limited to one bin and/or a SKU list) is taken at open. A count covers the **on_hand** bucket only (damaged/expired/blocked have their own flows). Each count entry records, under the position lock, the system on_hand of that bin row at the moment of counting (`system_qty`; for serialized items also the live serials there). Variance = counted − system_qty; at apply, under the position + bin locks, that variance is posted against the *current* balance, so postings between the count entry and apply are neither lost nor double-counted (INV-023). Found → `adjustment_in` at WAC, loss → `adjustment_out`; I-07 applies (a loss can't take reserved units → `reserved_conflict`). A line is large when |variance| > `countRecountPct` % of system_qty (any variance when system_qty = 0): submit sends un-recounted large lines back to counting automatically (one forced recount per line; the recount stands). Serialized lines list serials: scanned − system = found (a new unit, or a `lost` unit of the same variant re-activated), system − scanned = missing (unit → `lost`); a serial live elsewhere is rejected at entry. Approval amount = Σ |variance| × WAC.
**Damage/Repair/Disposal (new, normative):** damage draft → submitted → approved → applied (`damage` movement); repair request → approved → applied (`repair_to_stock`); disposal request → approved (owner/manager threshold) → applied (`disposal`, terminal loss). All enforce I-07.
**Transfer:** draft → submitted → approved → in_transit(ship) → partially_received → completed. submitted→rejected→draft. pre-ship→cancelled. completed with acknowledged variance→closed_with_variance. Post-ship cancel forbidden.
**Adjustment:** draft → submitted → approved → applied. Kind `opening` (flow 26) applies on approval, like damage/repair/disposal. submitted→rejected→draft. applied terminal (correction via new adjustment). Void pre-apply→cancelled.
**Purchase Return:** draft → submitted → approved → shipped → supplier_confirmed → closed. rejected→draft; supplier_rejected→quarantine decision.
**Sales Return:** requested → approved → received → inspected → restocked|written_off (terminal). rejected/cancelled exits pre-receive.
**Reservation:** active → partially_fulfilled → fulfilled; active→cancelled|expired (release). Partial fulfil loops.
**Product/Variant:** draft → active ↔ inactive → discontinued → archived. Archived terminal (re-activate needs admin + audit, creates new version note; transactions still blocked for old history clarity — prefer clone).
**Receipt/Count lines:** posted immutable; corrections via new docs only.

Guards: every transition checks permission + company scope + warehouse scope + state precondition + `version` match + invariant (e.g., ship checks ATP and I-07) in one transaction; failed guard rolls back + audit `transition.denied`.
